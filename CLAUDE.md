# Body of Evidence

> Generated by Claude Panel on 2026-05-05. Do not edit by hand — regenerate via the panel.

**Stack:** React, Vite, Three.js, React Three Fiber, GSAP, Firebase

## Overview

Interactive web app (desktop/iPad only) for Zoryve that lets clinicians browse before/after patient photographs from Roflumilast clinical trials through a 3D cylindrical carousel driven by a multi-select filter panel (indication, formulation, body area, severity, age, sex). Built as a non-responsive desktop experience — not intended for mobile.

Data source is a single JSON (`iCVA 2.1`) of patient records, each containing up to 8 timepoint images (baseline, week1…week52) plus scoring data (IGA/v-IGA-AD/S-IGA, WI-NRS, SI-NRS). Clicking a carousel image opens a DetailOverlay showing the full timepoint journey with scale legends.

## Architecture

State lives in singleton managers under `src/managers/` — DataManager (JSON loading + filtering), FilterManager (filter state), PoolManager (carousel slot pool), RotationStateManager (rotation + GSAP tweens), ImageManager (Three.js texture preload), AppStateManager (lifecycle LOADING→INTRO→MAIN→DETAIL), DebugManager (URL-triggered debug overlay). Components never import managers directly for state — they read via `useManagerSubscription(manager, selector)` hooks.

Cross-manager and UI↔manager communication runs through a single `EventSystem` pub/sub bus in `src/utils/EventSystem.js`. Event names are centralised on `EventSystem.EVENTS` with naming convention: past-tense for state changes emitted by managers (FILTER_CHANGED, IMAGES_UPDATED), present/request for user intents emitted by components (FILTER_SELECTED, NAVIGATION_REQUESTED).

Carousel is a virtual cylinder: images laid out around a 3D cylinder, rotated around Y axis. Rows/visible-columns adapt to result count (SMALL: 1×5 for 2+, MEDIUM: 3×7 for 21+, LARGE: 5×11 for 45+). PoolManager creates `visibleColumns + 2×poolBuffer` slots and reassigns images to slots as rotation changes — an infinite-scroll pattern that keeps Three.js object count constant regardless of dataset size.

## Rules

- Do not import managers from components to read state directly — use `useManagerSubscription(manager, selector)` so renders stay reactive and unsubscribes are handled. Calling manager methods to *emit intent* (e.g. `filterManager.reset()`) is fine, but state reads must go through the hook.
- Three.js/React Three Fiber setup uses `alpha: true, antialias: true`, transparent background, and `touchAction: 'none'` on the Canvas style to suppress default scroll gestures during drag. Ambient light at intensity 0.8 is the only light — images are unlit basic materials.

## Conventions

- All constants (PATIENT_SCHEMA, FILTER_KEYS, FILTER_DEFINITIONS, APP_STATE, ROUTES, NAVIGATION_DIRECTION, ASSETS, DATA_SOURCE_KEY, COLOURS) live in `src/constants/index.js`. Carousel-specific constants (CAROUSEL_LAYOUT, CAROUSEL_SETTINGS, CAROUSEL_VISIBILITY, CAROUSEL_FRAME, DRAG_THRESHOLD) are isolated in `src/constants/carousel.js`. No magic strings anywhere — every status/route/field/key name is imported from constants.
- Filters use an index-based system: each FILTER_DEFINITIONS entry has an `options` array whose array index IS the filter ID. FilterManager stores selected indices as arrays (multi-select) or single-item arrays (single-select). Benefits: no string parsing for age ranges (pre-computed min/max), faster Set operations, and type-safe numeric indices.
- Every manager exposes `subscribe(cb)` returning an unsubscribe function, plus an internal `notifyListeners()` that wraps each callback in try/catch. Same pattern across DataManager, FilterManager, PoolManager, RotationStateManager, AppStateManager — keeps React updates decoupled from the event bus.
- Page/view composition: `App.jsx` routes to `pages/IntroPage` or `pages/MainPage`. MainPage mounts `views/MainView`, which hosts the R3F `<Canvas>` wrapping `views/Carousel3DScene`. Carousel3DScene contains the rotation group and maps PoolManager slots to `components/carousel/ImageFrame` instances. DetailOverlay, NavigationArrows and Shadow are siblings inside MainView.
- Deployment is Firebase Hosting — `firebase.json` serves `dist/` with SPA rewrites (everything → `/index.html`). `npm run deploy` runs `vite build && firebase deploy`. Project id lives in `.firebaserc`.
- Colour palette is Zoryve brand-locked: Zoryve Blue `#408BAB`, Zoryve Midnight Blue `#14365B`, Zoryve Yellow `#FDE939`, Zoryve Black `#1F2B2B`, white `#FFFFFF`. Used for filter gradients (#21679E→#154E80 for Clinical Trial tab), headers and selected-state glows (FDE939 with 6–20px spread).
- Tailwind is present in devDependencies but the codebase uses global CSS custom properties + per-component `.css` files (e.g. `MainView.css`, `DetailOverlay.css`). Treat Tailwind as scaffolding baggage, not an active style system — write new styles as scoped `.css` files next to the component.
- Inter is the global font across weights. Filter headers: Inter SemiBold 12px. Basic button: 10px uppercase regular weight, 100px min width × 40px height, 6px radius, #1378A8 background. Selected button state: white bg, #1F2B2B content, 20px #FDE939 glow. These are spec constants from the PRD and appear repeatedly across components.

## Gotchas

- Patient `age` field arrives as string or number from JSON — DataManager.loadData() normalises to number via `parseInt` on every record after load. Age range matching (`ageRange` matchFunction) assumes numeric and guards with `typeof === 'number' && !isNaN(age)`.
- Filter value matching is case-insensitive (`String(fieldValue).trim().toLowerCase() === option.value.toLowerCase()`) to survive patient-data entry variation (e.g. `Torso` vs `torso`). Gender is the exception — uppercase comparison against one-letter codes 'M'/'F' via GENDER_MAP.
- Body Area filter uses `bodyAreaSimple` (not raw `bodyArea`) — this is a normalised field mapped to the four filterable buckets (Head and neck, Torso, Arms and hands, Legs and feet). A script `scripts/add-body-area-simple.js` populates it from the free-text `bodyArea` field. A fifth filter option matches `multiBodyArea === true` via the `matchField` escape hatch.
- `getFirstValidImage(patient)` returns the earliest timepoint image (baseline → week1 → … → week52) that is non-empty. This is what shows on the carousel — only one photo per patient — so a patient without a baseline still appears via their first available weekly photo.
- A patient can appear multiple times in the dataset with the same `patientId` but different `bodyArea` values (when multi-body-area is tracked). `getRelatedPatients(patientId)` returns all entries sorted alphabetically by bodyArea and powers the DetailOverlay's BodyAreaSelector.
- Filter-changed and images-updated events clear the selected image (overlay closes automatically). Debug mode (`debugManager.getIsDebugMode()`) bypasses this so the overlay stays open when FilterManager quietly sets filters to highlight them in the UI via `setFiltersQuietly()`.
- SVG assets in `public/UI/` are exported at 2× intended display size — components apply 50% scaling in CSS. This is a deliberate convention described in the PRD; don't treat the apparent size mismatch as a bug.
- StrictMode double-mounts effects during development. `useCarouselManager` guards init with `isInitialisedRef.current` so the pool is built once — without this guard the pool flickers/double-populates on mount.

## Patterns

- `useManagerSubscription(manager, selector)` and `useEventSubscription(event, handler, deps)` are the only two ways React touches manager/event state. They initialise state via the selector, resubscribe on dependency change, and auto-unsubscribe on unmount — this is the codebase's replacement for Context/Redux.
- Carousel state transitions use a crossfade: `useCarouselManager` stores pending updates in a ref, fades the container with GSAP to opacity 0, applies the new layout/images/rotation while invisible, then fades back in. If multiple filter changes fire during the fade-out, only the latest pendingRef value is applied — earlier updates are dropped deliberately.
- Filter availability is recomputed on every filter change: `dataManager.getAvailableFilterOptions(filtersExcludingTarget, targetFilter)` returns the Set of option indices that would still yield results. FILTER_AVAILABILITY_CHANGED event drives UI dimming of unavailable filter chips — never disable, always indicate.
- Drag vs click disambiguation in the 3D scene uses a threshold (10px via DRAG_THRESHOLD) plus a shared `clickRef.current.isDragging` flag that is set true once the threshold is crossed and cleared with a 50ms setTimeout on pointerUp. ImageFrame onClick handlers check this ref so releasing after a drag never fires the image-selected click.
- ImageManager preloads every patient thumbnail (converts `foo.jpg` → `foo_thumb.jpg`) into Three.js textures during the loading screen. Thumbnails are looked up by original image path. Full-size images are only loaded on demand in the DetailOverlay. Budget: ~500 thumbs @ 512² ≈ 500MB GPU memory, considered acceptable for desktop.
- Camera FOV is computed per layout via `calculateBestFitFOV(layoutConfig, aspectRatio, padding)` which takes the larger of fovForHeight and fovForWidth (treating visible arc as ~117° of the cylinder). This keeps the carousel correctly framed across aspect ratios and row counts without hard-coding.
- Image visibility falls off by angle from centre: full opacity within ±18° (π/10), linear fade through ±30° where a dark overlay kicks in, zero opacity at ±90°. Beyond cutoff (π/2) slots return `visible: false` and skip rendering. Values live in CAROUSEL_VISIBILITY.
- Snap-to-column after drag: on pointerUp, `calculateSnapTarget(rotation, columnAngle) = round(rotation / columnAngle) * columnAngle` picks the nearest column and GSAP tweens there with `power2.out` over snapDuration (0.5s). NavigationArrows fire NAVIGATION_REQUESTED events; RotationStateManager handles them by tweening ±1 column.

## Decisions

- Practice-Based data source was removed (commit 2a15e4c). Only Clinical Trial data (`iCVA 2.1` key in patient_data.json) remains. The Practice-Based tab and its background assets were stripped but the filter panel shell still reserves header styling for a future two-source split.
- Per-tier auto-spin (commit 804cbbd): on first load and after each filter change the carousel spins a configurable number of columns (`autoSpinColumns`: 5 for LARGE/MEDIUM, 4 for SMALL) via `rotationStateManager.autoSpin()` using GSAP — signals interactivity without waiting for the user to drag.
- Routing uses BrowserRouter with three paths: `/` (IntroPage), `/main` (MainPage), and `/debug/*` which renders MainPage but with DebugManager parsing URL params to open a specific patient's overlay. Debug URLs follow `/debug/:patientId/:bodyArea[/:imageIndex]` with hyphenated body areas (e.g. `antecubital-fossa`) normalised back to title case.

## Universal Rules

- British English throughout — code, comments, UI copy, commit messages
- **Keep files lean**: No file should be doing too many things. Split large files by concern. If a component or controller is growing past ~300 lines, it probably needs breaking up.
- **Co-locate by domain**: Group files by what they do, not by type. Keep related code together.
- **Challenge the frame**: Ask whether the question itself is right before answering it. Could the problem be dissolved rather than solved?
- Section separators: `// ------------------------------------------------------------` comments to divide files into logical sections
- No file path comments at the top of files
- Conventional commits: `feat:`, `fix:`, `refactor:`, `cleanup:`, `docs:`
- No utility-first CSS frameworks. Judge per project — custom properties + modules, or whatever fits.
- **Don't repeat yourself**: Extract shared logic into reusable components, utilities, and helpers. If you see the same code block in multiple files, refactor it into one place.
- **Flat where small, grouped when big**: Don't create folders for 1-2 files. Max 3 levels deep.
- **Diverge before converging**: On any design, architecture, or planning question — before recommending an approach, briefly map the solution space. Name at least one conventional path, one underexplored path, and one that seems wrong at first glance but might not be. Then recommend with explicit reasoning. Don't pad responses with obviously worse alternatives — the goal is finding the best answer, not the most expected one.
- **Virtual team for code**: Any task writing or significantly modifying 3+ files must use the virtual-team-development skill — Architect review first, then parallel developer agents, then Lead Review, then QA. Never write multi-file features alone.
- **Invoke skills proactively**: Don't wait to be asked. If a skill matches the task, use it.
- Short inline comments — state intent or explain non-obvious decisions, never restate what code already says
- Don't add comments, docstrings, or type annotations to code you didn't change
- Don't include `Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>` etc
- Don't commit `.env` files or secrets
- Don't push unless asked
- Don't over-engineer: no feature flags, no backward-compat shims, no premature abstractions
- Don't add error handling for scenarios that can't happen
- Don't create helpers or utilities for one-time operations — three similar lines is better than a premature abstraction
- Don't duplicate code across files — if the same logic appears twice, extract it
- Don't let files bloat — split by concern before they become unwieldy
- Thin orchestrators, rich components — page-level components compose and arrange, they don't contain business logic or complex UI. Push logic into focused sub-components.
- State ownership: centralised managers own state. Components subscribe via hooks — never import managers directly. Cross-manager communication via events, not direct method calls.
- Always use a shared API client with auth token injection — never raw fetch/axios scattered throughout the codebase.
- Build shared UI primitives (buttons, badges, modals, empty states) once and reuse everywhere. Don't rebuild the same pattern in each page.
- Consistent API response shape — define a standard envelope for success and error responses. Every endpoint, every time.
- Structured logging — use a proper logger, never console.log in production server code.
- Validate inputs at the boundary — validate request bodies with schemas before they reach controller logic.
- Don't expose secrets in client-side bundles — anything baked into the JS at build time is publicly visible.
- Decouple logic from frameworks — business logic, state, and inter-component communication should be framework-agnostic. Use plain classes, managers, and event systems so logic can be understood, tested, and reused without framework dependencies.
- No magic strings — all statuses, routes, collection names, tier values, and config keys must come from named constants in a single source of truth. Never hardcode string literals that represent state or identity.
- Prefer loose coupling — components communicate through events and subscriptions, not direct method calls or deep prop chains. If changing one module requires changing another, the boundary is wrong.
