## Overview

Body of Evidence is a desktop/iPad-only pharma promotional web app for Zoryve (Arcutis) that lets clinicians explore before/after patient photographs from Roflumilast clinical trials. A multi-select filter panel (indication, formulation, body area, severity, age, sex) drives a 3D cylindrical carousel of patient images, clicking any image opens a DetailOverlay with the full timepoint journey and clinical scoring data. No backend, no user accounts, no data collection. Pure static site deployed to Firebase Hosting.

The app is desktop/iPad only, intended for use by medical representatives and clinicians at point-of-care or in presentations. It renders patient photograph datasets from a JSON file, applying filters client-side with no server round trips. All interactions are ephemeral, there is no persistence layer, login, or analytics. Designed to meet pharma regulatory requirements by avoiding any transmission or storage of clinical photograph data.

## Architecture

Project blueprint: React SPA + React Three Fiber 3D carousel deployed as a pure static site to Firebase Hosting. All state lives in seven singleton managers (DataManager, FilterManager, PoolManager, RotationStateManager, ImageManager, AppStateManager, DebugManager) with no Redux or Context. EventSystem pub/sub bus handles cross-manager communication. Two rendering layers coexist in the same viewport: a React Three Fiber Canvas (3D carousel) and HTML layers (filter panel, detail overlay). HashRouter + Vite base './' for Veeva/deep-path hosting. No backend, no user accounts.

All application state lives in seven singleton managers under src/managers/. Components never import managers for state reads, they use useManagerSubscription(manager, selector) exclusively. Manager methods may be called to emit user intent. Cross-manager communication goes through EventSystem.EVENTS, never direct method calls between managers. Adding a new state concern means a new manager file, not extending a global store.

Composition hierarchy: App.jsx → HashRouter → IntroPage | MainPage → MainView → [Canvas > Carousel3DScene > ImageFrame instances] + NavigationArrows + Shadow + DetailOverlayContainer. DetailOverlay and FilterPanel are sibling HTML layers. Data flow: DataManager loads patient_data.json → FilterManager applies selections → IMAGES_UPDATED event → PoolManager reassigns slots → RotationStateManager triggers auto-spin → ImageFrame components re-render. All triggered by events, not prop chains.

The 3D carousel is a virtual cylinder in React Three Fiber. PoolManager creates a fixed number of Three.js slots (visibleColumns + 2×poolBuffer) and reassigns images to slots as rotation changes, keeping GPU object count constant regardless of dataset size. Three layout tiers by image count: SMALL (1 row × 5 cols, 2+ images), MEDIUM (3 rows × 7 cols, 19+), LARGE (5 rows × 11 cols, 45+). Camera FOV is computed per-tier via calculateBestFitFOV() to keep the carousel correctly framed across aspect ratios.

## Rules

- The app has no backend, no user accounts, and no data collection. All state is ephemeral and lost on page reload. Firebase Hosting serves only static files. This constraint is intentional for pharma regulatory compliance, no special category health data (patient photographs) may be transmitted to or stored on an agency-controlled server.

## Conventions

- SVG assets in public/UI/ are exported at 2× intended display size, components apply 50% scaling via CSS. The apparent size mismatch is intentional (from the PRD), giving crisp rendering on retina/HiDPI displays without srcset. Do not 'fix' the apparent oversize by removing the CSS scale.
- All constants live in src/constants/index.js (PATIENT_SCHEMA, FILTER_KEYS, FILTER_DEFINITIONS, APP_STATE, ROUTES, NAVIGATION_DIRECTION, ASSETS, COLOURS) and src/constants/carousel.js (CAROUSEL_LAYOUT, CAROUSEL_SETTINGS, CAROUSEL_VISIBILITY, CAROUSEL_FRAME, DRAG_THRESHOLD). No magic strings anywhere. Helper functions getFilterOption(key, index), getFilterDisplay(), and getFilterValue() provide type-safe constant lookups.
- Colour palette is Zoryve brand-locked: Blue #408BAB, Midnight Blue #14365B, Yellow #FDE939, Black #1F2B2B, White #FFFFFF. Clinical Trial filter tab uses gradient #21679E→#154E80. Selected states glow with FDE939 at 6–20px spread. All values live in the COLOURS constant in src/constants/index.js and are repeated in per-component CSS files.
- Styles use global CSS custom properties plus per-component .css files co-located with each component (e.g. DetailOverlay.css next to DetailOverlay.jsx). Tailwind is present in devDependencies as scaffolding baggage but is not actively used, write new styles as scoped .css files, not Tailwind classes.
- Event naming convention: past-tense for state changes emitted by managers (FILTER_CHANGED, IMAGES_UPDATED, APP_STATE_CHANGED), present/request-tense for user intents emitted by UI components (FILTER_SELECTED, NAVIGATION_REQUESTED, IMAGE_SELECTED). All 16 event names live on EventSystem.EVENTS, never use raw strings when subscribing or emitting. [conflicts with another entry, verify]
- Thumbnail paths are derived from full image paths by replacing .jpg with _thumb.jpg (e.g. 101-023_baseline.jpg → 101-023_baseline_thumb.jpg). This convention must be consistent across ImageManager (preloading) and patientDataSplitter (timepoint card construction). Both rely on this string transform, there is no separate thumbnail field in the data.

## Gotchas

- Patient age field arrives as string or number from the source JSON. DataManager.loadData() normalises all age values to numbers via parseInt after load. Age range matching guards with typeof age === 'number' && !isNaN(age). Do not assume age is already a number when reading from raw patient records.
- Filter string matching is case-insensitive for all fields except gender, String(fieldValue).trim().toLowerCase() === option.value.toLowerCase(). Gender uses uppercase M/F codes via GENDER_MAP because the patient data stores one-letter uppercase codes. Applying lowercase comparison to gender would break all gender filter matches.
- Body Area filter uses the normalised bodyAreaSimple field (not the raw bodyArea free-text field). A fifth option matches multiBodyArea === true via a matchField escape hatch in FILTER_DEFINITIONS. The script scripts/add-body-area-simple.js populates bodyAreaSimple from raw bodyArea text, run this script whenever patient data is updated.
- A single patientId can appear multiple times in the dataset with different bodyArea values when a patient has multiple body areas being tracked. getRelatedPatients(patientId) returns all entries sorted alphabetically by bodyArea and powers the BodyAreaSelector tab in DetailOverlay. Always use patientId + bodyArea together as a unique key, not patientId alone.
- React StrictMode double-mounts effects in development. useCarouselManager guards pool initialisation with an isInitialisedRef.current boolean so the pool is built exactly once, without this guard the pool flickers and double-populates on mount. Any useEffect that initialises a singleton resource needs this pattern.
- Filter-changed and images-updated events automatically clear the selected image so the DetailOverlay closes. DebugManager sets a global isDebugMode flag that AppStateManager checks to suppress this behaviour, the overlay stays open during debug URL activation so the debug patient remains visible while FilterManager quietly sets filters via setFiltersQuietly().
- Image visibility falls off by angle from the carousel centre: full opacity within ±18° (π/10 radians), linear fade through ±30° where a dark overlay starts, zero opacity at ±90°. Beyond ±90° slots return visible: false and skip rendering entirely. These values live in CAROUSEL_VISIBILITY constants, do not hard-code angle thresholds in component code.
- Per-tier auto-spin fires on first load and after each filter change: the carousel sweeps autoSpinColumns (5 for LARGE/MEDIUM, 4 for SMALL) via rotationStateManager.autoSpin() using GSAP. This is a deliberate UX signal of interactivity. The spin must complete before drag interaction registers, so do not call autoSpin() while isAnimating is true.

## Patterns

- useManagerSubscription(manager, selector) and useEventSubscription(event, handler, deps) are the only two ways React components touch manager or event state. Both hooks initialise from current state, resubscribe on dependency change, and auto-unsubscribe on unmount, replacing Context and Redux entirely. Never import a manager singleton directly inside a component for state reads.
- Filter state uses an index-based system, FILTER_DEFINITIONS[key].options is an array and the array index IS the filter ID. FilterManager stores selected indices as number arrays. Benefits: no string parsing for age ranges (pre-computed min/max on options), faster Set operations using integers, type-safe lookups via getFilterOption(key, index). Filter availability is emitted as a Set of available indices via FILTER_AVAILABILITY_CHANGED.
- Carousel state transitions use a GSAP crossfade: useCarouselManager stores the pending update in a ref, fades the container to opacity 0, applies the new layout/images/rotation while invisible, then fades back in. Only the latest pendingRef value is applied inside the onComplete callback, if N filter changes fire during a fade, all but the newest are discarded.
- Filter availability is recomputed on every filter change by running the full filter pipeline with each target filter temporarily removed, then collecting the option indices that any surviving record matches. A Set of available indices per filter type is emitted as FILTER_AVAILABILITY_CHANGED, UI components check membership for dimming (never disable, always dim). This preserves discoverability while signalling fruitlessness.
- DetailOverlay timepoint selection: splitPatientData() in src/utils/patientDataSplitter.js prefers baseline + week2 + week8 when all three exist, then fills up to 3 timepoints from remaining available ones. A timepoint is available only if it has both an image and a score, rows without both are silently skipped. 'Not Reported' score values are filtered out.
- Debug mode activates via URL patterns (/debug/:patientId/:bodyArea/:imageIndex). DebugManager parses the route, injects the detail overlay directly, and calls setFiltersQuietly() to highlight matching filters without triggering the filter-change events that would close the overlay. Useful for client and QA demos targeting a specific patient without disrupting normal app state flow.
- All managers follow the same subscribe/notify pattern: subscribe(callback) returns an unsubscribe function; internal state changes call _setState() which calls notifyListeners(). Components read current state via manager.getState() on mount then subscribe to updates. Each manager also uses _onEvent()/_cleanupEvents() from a BaseManager base class for HMR-safe EventSystem listener registration.

## Decisions

- Uses HashRouter (not BrowserRouter) with Vite base: './' for Veeva deep-path hosting compatibility. All asset paths use relative './' so the bundle works from any hosting subdirectory. BrowserRouter was ruled out after discovering it breaks on hard reload or direct deep-link access when deployed to a subdirectory path.
- Images use Three.js MeshBasicMaterial (unlit), not PBR materials. Ambient light at intensity 0.8 is the only light in the scene. This is deliberate, patient photographs must render as close to neutral/true colour as possible. PBR lighting would shift perceived skin tones, which is unacceptable in a clinical context.
- ImageManager preloads every patient thumbnail into Three.js textures during the loading screen (~500 thumbs at 512² ≈ 500MB GPU, acceptable for desktop). Full-size images load on demand in DetailOverlay only. Thumbnails are stored in a Map keyed by original image path. This eliminates texture pop-in during carousel interaction at the cost of a longer initial load.
- The R3F Canvas uses alpha: true, antialias: true with transparent background and touchAction: 'none' on the Canvas style to suppress default scroll gestures during drag. The transparent canvas allows the HTML background image to show through behind the 3D carousel without a separate compositing layer.
- Practice-Based data source was removed (commit 2a15e4c). Only Clinical Trial data (iCVA 2.1 key in patient_data.json) remains. The Practice-Based tab and its background assets were stripped, but the filter panel shell retains header styling reserved for a possible future two-source split, a deliberate architectural placeholder, not dead code.
